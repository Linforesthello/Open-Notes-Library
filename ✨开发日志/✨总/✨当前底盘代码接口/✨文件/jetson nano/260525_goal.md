### 1.3 当前局限

- 容器退出即删除（`--rm`），修改不持久化（engine 在挂载卷中保留）
- Python 推理管线 CPU 瓶颈明显（~4.2 FPS），GPU 推理只占 19% 时间
- ARM Cortex-A57 单核性能有限，预处理/后处理成为瓶颈
- UFF 格式已逐渐被 NVIDIA 弃用，ONNX 是主流方向

## Part 2：总体规划：Docker 内验证 ONNX → 逐步扩展生态

### 2.1 核心策略

**Docker 作为当前稳定开发壳，先在容器内验证 ONNX→TensorRT 链，再决定是否原生安装。**

```
完成: Docker + SSD-MobileNet (UFF) + YOLOv5n (ONNX→Engine + Python 推理脚本)
  │
  ├──→ 第一阶段: Docker 内 ONNX→TensorRT 验证 ✅ 完成
  │        yolov5n.onnx → trtexec → engine → benchmark
  │        实际: 45.8ms GPU Compute, 20.9 FPS
  │
  ├──→ 第二阶段: Python 推理脚本 + 多模型扩展（推理脚本 ✅ 完成）
  │        detect_yolov5n.py → ~4.2 FPS 端到端 → HTTP MJPEG 推流
  │        CPU 瓶颈: 预处理 ~80ms + 后处理 ~100ms > GPU 推理 ~46ms
  │
  └──→ 第三阶段: 按需原生安装 + 完整开发闭环
         仅当需要改源码、系统级集成时再做
```

### 2.2 关键认知

| 误区 | 纠正 |
|------|------|
| ❌ Docker 不适合开发，必须原生 | ✅ Docker 适合做模型验证，挂载卷保证持久化 |
| ❌ ONNX 管线依赖原生环境 | ✅ TensorRT 的 `trtexec` 和 Python API 在容器内完全可用 |
| ❌ 先装好原生再搞模型 | ✅ 先隔离验证模型链，再决定是否原生，风险更小 |
| ❌ 一次搞定所有模型 | ✅ 先留一个 UFF 基线 + 加一个 ONNX 测试，稳定后再扩 |

### 2.3 持久化策略

Docker 的挂载卷已经覆盖了关键数据目录，模型资产不会丢失：

```
宿主机 ~/jetson-inference/  (持久化)
  ├── data/                  ← 模型、engine、测试图片都放这里
  ├── python/training/classification/data/
  ├── python/training/classification/models/
  ├── python/training/detection/ssd/data/
  ├── python/training/detection/ssd/models/
  └── python/www/recognizer/data/

容器内 /jetson-inference/  (运行时)
  └── 以上目录自动挂载 ← 同一份数据
```

**工作流**：在宿主机把模型文件放入 `data/` → 进容器直接读取，退出不会丢失。

## Part 3：第一阶段 — Docker 内 ONNX→TensorRT 验证（已完成）

### 3.1 策略说明

**全程在 Docker 容器内完成，未安装任何原生环境。** 所有 ONNX 转换和验证都在 `dustynv/jetson-inference:r32.7.1` 容器内完成。

| 对比项 | 旧计划（原生优先） | ✅ 实际执行 |
|--------|-----------------|-----------|
| 第一件事 | 编译原生 jetson-inference | **trtexec 转 yolov5n.onnx → engine ✅** |
| 原生安装 | ✅ 必须 | ⏸ 按需（跳过） |
| Docker | ⏸ 过渡 | ✅ 当前稳定壳 |
| 模型持久化 | 系统目录 | 挂载卷 `data/` ✅ |
| trtexec 路径 | 系统 PATH | `/usr/src/tensorrt/bin/trtexec` |
| 风险 | 编译失败/环境破坏 | 低，容器隔离 ✅ |

### 3.2 任务分解

#### Step 1：将模型放入挂载目录（持久化）

```bash
# ✅ 已完成
mkdir -p ~/jetson-inference/data/models/yolov5n
cp ~/models/yolov5n.onnx ~/jetson-inference/data/models/yolov5n/
```

进入容器后可以在 `/jetson-inference/data/models/yolov5n/yolov5n.onnx` 访问到。

#### Step 2：在 Docker 容器内用 trtexec 转换 ONNX→Engine（✅ 已完成）

```bash
# 进入容器
cd ~/jetson-inference && docker/run.sh

# 实际成功命令（trtexec 在 /usr/src/tensorrt/bin/，不在 PATH）
/usr/src/tensorrt/bin/trtexec \
  --onnx=/jetson-inference/data/models/yolov5n/yolov5n.onnx \
  --saveEngine=/jetson-inference/data/models/yolov5n/yolov5n_fp16.engine \
  --fp16 --workspace=256 \
  --minShapes=images:1x3x640x640 \
  --optShapes=images:1x3x640x640 \
  --maxShapes=images:1x3x640x640
```

**输出**：生成 `yolov5n_fp16.engine` 文件（7 MiB），持久化在挂载卷中。

**实际耗时**：首次构建 ~688 秒（11.5 分钟），之后加载只需 ~4.4 秒。

**关键参数说明**：
| 参数 | 选值 | 原因 |
|------|------|------|
| `--optShapes` | `images:1x3x640x640` | ONNX opset 14 动态形状必须显式指定（TRT 8.2 不支持 `--inputShapes`） |
| `--workspace=256` | 256 MB | Nano 仅 4GB 共享内存，workspace 太大导致 OOM |
| `--fp16` | ✅ | 半精度推理 |

**注意**：`trtexec` 全路径为 `/usr/src/tensorrt/bin/trtexec`，可创建软链到 `/usr/local/bin/`。

#### Step 3：验证 engine 推理（✅ 已完成）

```bash
# 加载 engine 跑 100 次迭代 benchmark
/usr/src/tensorrt/bin/trtexec \
  --loadEngine=/jetson-inference/data/models/yolov5n/yolov5n_fp16.engine \
  --iterations=100
```

**实际结果**：
- Throughput: **20.87 qps**
- GPU Compute Time: **mean 45.76 ms, median 45.45 ms**
- Engine 加载时间: **4.44 秒**
- 稳定性: 45.27~49.71 ms 范围，无严重抖动

#### Step 4：编写自定义 Python 推理脚本（✅ 已完成，见第二阶段）

引擎已验证稳定后，编写了完整 Python 推理脚本 `detect_yolov5n.py`，包含：
- TensorRT engine 加载 + pyCUDA 缓冲区分配
- letterbox 预处理 / 异步推理 / 3 检测头解码 + NMS / 坐标反算
- 视频保存 (AVI, MJPG) + HTTP MJPEG 推流 (`--stream`)
- 滑动窗口 FPS 统计

**端到端性能：~4.2 FPS**（瓶颈在 ARM CPU 预处理/后处理）

#### Step 5：对比基线（✅ 已完成）

| 指标 | SSD-Mobilenet-v2 (UFF) | YOLOv5n (ONNX→TensorRT) |
|------|----------------------|------------------------|
| 输入尺寸 | 300×300 | 640×640 |
| 参数量 | ~5M | ~1.9M |
| GPU Compute Time (FP16) | **42.3 ms** | **45.8 ms** |
| FPS (FP16) | **~23** | **~20.9** |
| 精度 (COCO mAP) | ~22% | ~28% |
| 格式 | UFF（弃用趋势） | ONNX（主流标准） |
| Engine 大小 | — | 7 MiB |
| Engine 加载时间 | — | ~4.4 s |

## Part 4：第二阶段 — 多模型支持

### 4.1 Python 推理管线（已完成）

自定义推理脚本 [detect_yolov5n.py](jetson-inference/data/detect_yolov5n.py) 部署在容器内：

| 组件 | 说明 |
|------|------|
| 语言 | Python 3 + OpenCV + TensorRT Python API + pyCUDA |
| 预处理 | letterbox 缩放至 640×640, BGR→RGB→CHW, [0,1] |
| 推理 | TensorRT FP16 异步推理 (H2D→execute→D2H) |
| 后处理 | 3 检测头解码 (stride 8/16/32) → 置信度过滤 → NMS → 坐标反算 |
| 画框 | OpenCV 绘制检测框 + 标签 + 详情 |
| 输出 | AVI 视频保存 + HTTP MJPEG 推流 |

### 4.2 端到端性能分析

| 环节 | 耗时 | 占比 | 瓶颈 |
|------|------|------|------|
| GPU 推理 | ~46 ms | 19% | — |
| CPU 预处理 (resize+归一化) | ~80 ms | 34% | ARM Cortex-A57 |
| CPU 后处理 (decode+NMS) | ~100 ms | 42% | numpy 非向量化部分 |
| 画框 + JPEG 编码 | ~12 ms | 5% | — |
| **合计** | **~238 ms** | **100%** | **~4.2 FPS** |

### 4.3 视频推流

通过 `--stream` 参数启用 HTTP MJPEG 流：

```bash
python3 /jetson-inference/data/detect_yolov5n.py --stream --port 8080
```

- 纯 Python stdlib（`http.server`），零额外依赖
- 每个检测帧以 JPEG 60% 质量编码后推送
- 浏览器访问 `http://<nano-ip>:8080/stream` 实时观看
- 实测通过 RJ45 直连（10.10.3.70），延迟 ~5ms

### 4.4 模型优化技术

| 技术 | 说明 | 效果 |
|------|------|------|
| **FP16 推理** | 半精度浮点运算 | 2x 加速，几乎无损 |
| **INT8 量化** | 8 位整数量化 | 4x 加速，精度略降 |
| **TensorRT 层融合** | 自动合并网络层 | 减少显存访问 |
| **动态形状** | 可变输入尺寸 | 灵活部署 |
| **多流推理** | 并行处理多帧 | 提升吞吐量 |

### 5.4 TensorRT 关键 API 速览

```python
import tensorrt as trt
import pycuda.driver as cuda
import pycuda.autoinit

# 1. 创建 builder
logger = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(logger)

# 2. 构建网络
network = builder.create_network(
    1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH)
)

# 3. 解析 ONNX
parser = trt.OnnxParser(network, logger)
success = parser.parse_from_file("model.onnx")

# 4. 配置
config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)
config.set_flag(trt.BuilderFlag.FP16)

# 5. 序列化引擎
serialized_engine = builder.build_serialized_network(network, config)

# 6. 加载引擎推理
runtime = trt.Runtime(logger)
engine = runtime.deserialize_cuda_engine(serialized_engine)

# 7. 创建执行上下文
context = engine.create_execution_context()

# 8. 分配 GPU 显存
inputs, outputs, bindings, stream = allocate_buffers(engine)

# 9. 执行推理
context.execute_async_v2(bindings=bindings, stream_handle=stream.handle)
cuda.stream.synchronize(stream)

# 10. 处理输出
output = outputs[0].host
```

### 7.3 常见问题预判

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| `trtexec: command not found` | 不在 PATH | 全路径 `/usr/src/tensorrt/bin/trtexec` 或创建软链 |
| `Unknown option: --inputShapes` | TRT 8.2 不支持该参数 | 使用 `--optShapes=input:1x3x640x640` 替代 |
| `Cask (isConsistent)` 卷积维度错误 | 未指定动态输入形状 | 加 `--minShapes/--optShapes/--maxShapes` |
| Engine 构建 OOM/被 kill | Jetson 仅 4GB 共享内存 | 减小 workspace 到 256MB，使用 FP16 |
| `Some tactics do not have sufficient workspace` | workspace 不够尝试所有优化 | ⚠️ **不是错误**，等待完成即可 |
| ONNX 解析失败 | 算子不兼容 | 使用 onnxsim 简化，或更换 opset |
| FPS 低于预期 | CPU 瓶颈 / GPU 降频 | `sudo nvpmodel -m 0` 开最大性能 |
| Python 管线 ~4 FPS | CPU 预处理/后处理瓶颈 | CSI 相机 (~8-10 FPS) 或 C++ 重写 (~15-18 FPS) |
| `server._frame` 无数据 | StreamServer 引用不一致 | handler 应通过 `self.server.stream_server._frame` 读取 |

### 7.4 本机性能模式切换

# 切换到最大性能模式 (10W)
sudo nvpmodel -m 0
