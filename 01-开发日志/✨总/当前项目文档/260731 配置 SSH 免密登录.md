## 一、一般化处理（通用流程）

### 原理

免密登录基于**非对称密钥对**：

```
客户端(发起方)                   服务端(被登录方)
  私钥 id_ed25519      ──持有──→  公钥 id_ed25519.pub
  (留在本地, 600 权限)             (写入 ~/.ssh/authorized_keys)
```

登录时服务端用公钥验证客户端私钥签名，密码不再是必需。

### 标准三步

**1. 客户端生成密钥对**（已有 `~/.ssh/id_ed25519` 可跳过）

```bash
ssh-keygen -t ed25519 -C "名字@机器名"   # 一路回车，passphrase 留空即可
```

**2. 公钥部署到服务端**

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@目标IP   # 输入最后一次密码
```

无 `ssh-copy-id` 时手动等价操作：

```bash
cat ~/.ssh/id_ed25519.pub | ssh user@目标IP \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**3. 验证**

```bash
ssh user@目标IP echo ok   # 不再要密码即成功
```

### 关键决策点：旧密钥是否覆盖？

生成前先确认旧密钥是否在用：

```bash
grep -r IdentityFile ~/.ssh/config 2>/dev/null          # 有没有配置引用
ssh user@目标IP echo ok                                  # 目标机是否已认旧钥匙
```

- 旧密钥**在用**（已部署到过机器）→ 不要覆盖，直接复用旧钥匙，重复执行 `ssh-copy-id` 无害。
- 已覆盖 → **所有之前部署过的机器都要重新 `ssh-copy-id`**，否则登录失败。
- 客户端私钥、服务端 `authorized_keys`、`known_hosts` 三者记录方向不同，不要搞混：
  - `known_hosts` = 服务端主机密钥（防中间人）
  - `authorized_keys` = 客户端公钥（免密凭据）

### 排错速查

| 现象 | 原因/解决 |
|:----|:---------|
| 仍要密码 | 服务端 `sshd_config` 确认 `PubkeyAuthentication yes`，改后 `sudo systemctl restart ssh` |
| Permission denied | 权限：客户端 `~/.ssh` 700 / 私钥 600；服务端 `~/.ssh` 700 / `authorized_keys` 600 |
| 权限正确仍失败 | 服务端 `tail -f /var/log/auth.log`，核对用户名与 home 路径 |
| IP 变了连不上 | DHCP 下 IP 会变，用 `~/.ssh/config` 别名 + 固定 IP 或改 HostName |

### 加分项：SSH config 别名

`~/.ssh/config` 添加后 `ssh r1` 即可：

```
Host r1
    HostName 192.168.1.210
    User lin
    IdentityFile ~/.ssh/id_ed25519
```

## 二、项目特化处理（本次实际执行）

### 涉及机器

| 机器 | IP | 角色 | 系统 |
|:----|:---|:-----|:-----|
| 开发机 (VM) `lin@lin-virtual-machine` | 192.168.1.204 | 开发调试（**本次为客户端**） | Ubuntu VM |
| 车载主控 Mini PC (N100) | 192.168.1.210 | 车载主控（**本次为服务端**） | Ubuntu 22.04 |

### 执行过程与决策

1. **旧密钥确认**：`~/.ssh/id_ed25519` 已存在 → 先检查是否在用：
   - `~/.ssh/config` 无 `IdentityFile` 引用 → 无配置依赖
   - `ssh lin@192.168.1.210 echo ok` 仍要密码 → 旧密钥未部署到 210
2. **决策**：旧密钥未在任何机器部署过，**覆盖无风险** → 输 `y` 覆盖，重新生成（passphrase 留空）。
3. **部署公钥**：`ssh-copy-id -i ~/.ssh/id_ed25519.pub lin@192.168.1.210` → `Number of key(s) added: 1`，成功。
4. **验证**：`ssh lin@192.168.1.210 echo ok` 无需密码 ✓
