# 七、为什么长 prompt 反而降低效果？

这是 Whisper 的特点。

Whisper initial_prompt 不是：

> 词库

而是：

> 解码上下文提示

它会影响：

* token 概率
* 解码路径
* 语言模型先验

所以：

输入：

```
机器人领域专业词汇：
ROS2...
...
Docker
```

太长：

可能导致：

```
模型过度关注prompt
```

结果：

普通中文下降。

# 十一、原因分析

不是 Whisper 问题。

而是录音链路。

完整流程：

```
键盘事件
 ↓
启动录音线程
 ↓
麦克风打开
 ↓
Audio Stream建立
 ↓
VAD检测
 ↓
缓存audio_buffer
 ↓
Whisper推理
```

---

## 开始丢字原因

启动瞬间：

```
麦克风stream还没稳定
```

前几十~几百 ms：

可能丢失。

类似：

摄像头打开：

第一帧黑屏。

---

## 结束丢字原因

停止：

```
释放录音
 ↓
处理buffer
```

如果太快：

尾部音频还在：

```
audio_buffer
```

没有完全进入。

1. 为什么中文自动输出繁体？

这是 Whisper 的一个已知行为。

Whisper 模型内部对于中文只有一个语言类别：

zh

它不会严格区分：

zh-CN 简体中文
zh-TW 繁体中文

所以 whisper.cpp 可能根据训练数据倾向输出繁体。很多用户遇到：

中文语音 → Traditional Chinese

的问题。

你的情况：

language=auto

实际上流程：

声音
 ↓
Whisper检测中文
 ↓
zh
 ↓
生成中文文本
 ↓
默认倾向繁体

不是 Vocalinux 转换的问题，是 Whisper decoder 输出习惯。

2. 解决方案一：固定中文 + 简体提示词（推荐）

Vocalinux 支持 whisper.cpp 高级参数，例如 Initial Prompt，可以影响输出风格。

找到：

~/.config/vocalinux/config.json

查看：

nano ~/.config/vocalinux/config.json

增加类似：

{
  "speech_recognition": {
    "language": "zh",
    "initial_prompt": "以下是简体中文普通话，请使用简体中文输出。"
  }
}

核心：

以下是简体中文普通话，请使用简体中文输出。

这个 prompt 会引导 Whisper 输出简体。类似方法已经被 whisper.cpp 社区验证。
