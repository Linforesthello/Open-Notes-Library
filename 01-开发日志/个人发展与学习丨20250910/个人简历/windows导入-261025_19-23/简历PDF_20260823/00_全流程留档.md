## 三、真实渲染链路

```
.md
 → markdown-it（GFM）
 → template/template.html（固定模板，内容直插 <body>，无外层容器）
 → 注入样式：
      ① styles/markdown.css      （插件默认，body 14px / 行高 22px / padding 0 26px）
      ② styles/markdown-pdf.css  （插件附加，body padding 0 12px）
      ③ 用户 styles（本项目的 resume.css，注入顺序在①之后 → 同优先级可覆盖）
 → Chromium printToPDF（A4 / 10mm / 无页眉页脚 / printBackground）
```

**关键事实**：`markdown.css` 里**没有 `h2` 的 margin 定义**（已逐行确认 218 行）。那些"标题上下大空白"来自**浏览器默认样式**：`p` 1em、`h2` 0.83em、`ul` 1em。所以只要用户 CSS 真正加载，就一定能压掉它们。

## 四、三个根因（每个都有证据）

### 根因 1：样式路径失效且静默跳过（最致命）

- 现象：改任何 CSS 都"没区别"
- 证据：profile `532aae18` 第 99–101 行
  ```json
  "markdown-pdf.styles": ["/home/lin/Lin_note/.../个人简历/resume.css"]
  ```
  `Test-Path` 该路径 → **False**（这是 Linux 路径，当前机器是 Windows）
- 机制：插件对不存在的样式文件**不报错、不提示**，直接跳过 → 只有默认样式生效
- 修复：改相对路径 + 相对解析开关
  ```json
  "markdown-pdf.stylesRelativePathFile": true,
  "markdown-pdf.styles": ["resume.css"]
  ```
  原理：`stylesRelativePathFile: true` 让 `resume.css` **相对 md 所在目录**解析 → 一版一目录、各用各的样式，且 Linux/Windows 通用

### 根因 2：字体族名差一个词

- 原版 CSS 写 `'Noto Sans CJK SC'`；本机装的是 **`Noto Sans SC`**（`NotoSansSC-VF.ttf`，族名 `Noto Sans SC`）
- 结果：Windows 上两个 CJK 名都不存在 → 回退 `Microsoft YaHei` → 观感"更壮、更黑"，与原版差得多
- 原版实际用的是 `DroidSansFallback`（Linux 上 Chromium 的兜底中文字体），与 Noto Sans SC 同为 Google 系、字形最接近
- 修复：`font-family: 'Noto Sans SC', 'Noto Sans CJK SC', 'Droid Sans Fallback', 'Microsoft YaHei', sans-serif`

### 根因 3：CSS 悬挂缩进把标签裁掉

- 现象：技能特长 6 个类别标签（导航与 SLAM / 状态估计 / ROS2 与系统 / 运动控制底座 / 强化学习 / 工程素养）在 PDF 里消失，只剩冒号和正文
- 错误写法：
  ```css
  p:has(> strong:first-child) { padding-left: 6.8em; text-indent: -6.8em; }
  p > strong:first-child { display: inline-block; min-width: 6.8em; }
  ```
- 机制：`text-indent: -6.8em` 把首行左移 6.8em，而标签本身又占 6.8em 宽 → 标签被推到页面左边界之外，整段被裁
- 证据：PDF 文本层去空白后 **1429 字符**，比对照基准（1462）**少 33**，正好是 6 个标签的字数
- 修复：回退为纯内联 `p > strong:first-child { white-space: nowrap; }`
- 修复后实测：**1462 字符 = 对照基准完全一致**，6 标签全部回来

放在 `_分析\`，用工作区自带 Python 运行（无需 pip 安装任何东西）。

```powershell
$py = 'C:\Users\86173\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe'
& $py _分析\pdf_layout.py <某PDF> <标签>
```

输出：页数、MediaBox、嵌入字体名、内容流数量、字号分布、文字包围盒、行基线间距中位数。

### 2. `pdf_text.py` — 文本层抽取（查"内容是否缺行"）

```powershell
& $py _分析\pdf_text.py <某PDF> _分析\out.txt
```

输出到 UTF-8 文件：逐字文本 + 关键段落存在性。**用法要点**：文本会被抽成"每字一行"，比对时先去掉所有空白再搜关键词；注意部分字形被映射成"康熙部首"（如 `长→⻓`、`工→⼯`、`人→⼈`），搜索时要用不含这些字的词。

### 结构适配流程（本次扩展的通用做法，可复用）

| 步 | 动作 | 本次结论 |
