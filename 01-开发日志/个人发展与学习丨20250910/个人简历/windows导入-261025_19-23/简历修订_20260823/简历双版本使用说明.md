## 二、两套结构怎么用

**展示版顺序**：个人信息 → 意向岗位 → GitHub → **核心能力（4–5 行）** → 获奖经历 → 教育背景 → 项目经历

**单页文字版顺序**：个人信息 → 意向岗位 → GitHub → **核心能力（5 行索引）** → **获奖经历** → **教育背景（一行）** → 项目经历 → 技能特长

> 2026-08-23 调整：单页版把"获奖经历"提到"教育背景"之前——**用国家级奖项先定调，把学校降级为背景信息**（与重排版的教育后移同源策略）。调整后单页版与重排版的教育位置一致，差异只在数据详略。

> ⚠️ 展示版与单页版顺序**不同**：展示版把教育背景放在获奖之后（同单页版），而**网申版**必须把教育背景放最前（ATS 要在前 1/3 区域抓学历与毕业年份字段）。三套不要互相照搬。

**网申版顺序**：个人信息 → 意向岗位 → GitHub → 教育背景 → 获奖经历 → 项目经历 → 技能特长

| 场景 | 用哪版 | 原因 |
|:--|:--|:--|
| 企业官网/招聘平台网申表单 | **网申版** | 学历/毕业时间是筛选硬字段，前置更稳；平台简历解析也按常规顺序更准 |
| 宣讲会、内推、邮件附件、打印 | **展示版** | HR 前 8 秒先看到技能与量化成果，而非学校标签 |
| 面试自带的纸质简历 | **展示版** | 面试官按你的顺序翻阅，重点前置 |

两版**内容完全一致**（同一批已核实的事实），只有区块顺序与技能区块的详略不同。改动素材时两边都要同步，或只维护展示版、投递网申时手工把技能区块移回末尾。

## 三、展示版顶部"核心能力"= 特征词索引（不含解释）

顶部只放**特征词/标签**，用 `｜` 分隔，一行一个能力族，不展开、不带数据、不带佐证——它的作用是让 HR/ATS 在 5 秒内抓到岗位关键词（含英文标签便于境外/外企 ATS 匹配）。

**A 版（运控）5 行**：运动控制/正逆运动学/PID 整定与系统辨识/LQR/MPC(了解) ｜ 电机闭环/CAN 总线协议设计/FOC/CSP 位置闭环/堵转保护/多节点分布式通信 ｜ 嵌入式与实时系统/C/STM32 HAL/FreeRTOS/SocketCAN/UART·SPI·I2C·RS485 ｜ 强化学习/PPO·SAC/Actor-Critic/Reward Design/并行环境训练/PyTorch→ONNX 部署 ｜ Linux/Git/Docker/MATLAB·Simulink

**B 版（规划控制）5 行**：运动控制/正逆运动学/PID 整定/LQR/MPC(了解)/里程计建模 ｜ 导航与定位/AMCL/MPPI/costmap 参数工程/EKF 融合/TF 坐标变换 ｜ SLAM 与建图/激光雷达/点云处理/标定/传感器融合 ｜ 路径规划与避障/采样优化/ROS2/Linux/系统集成与排障 ｜ 强化学习/PPO·SAC/仿真训练/Sim-to-Real/PyTorch·MuJoCo/ONNX 部署

> 格式约定：每行 3–5 个**能力族标签**（短的 2–6 字，长的用"XX 与 YY"），英文只保留行业通用缩写（AMCL/MPPI/SLAM/EKF/PID/CAN/ROS2/PPO/SAC/ONNX/LQR），**不写英文全称、不写括号解释、不带数据**。
> **用词禁用**：两版简历均不使用"具身智能/Embodied AI"（2026-08-23 定），需要表达该领域时用"强化学习运控""仿真训练与部署"等具体说法。

**详细技能在末尾"技能特长"**：仍按 9 类分门别类完整阐述（嵌入式 / 运动控制 / 强化学习 / 总线接口 / 传感器 / ROS2 / 工具链 / 工程素养 / 语言），带验证深度标注（实机 / 仿真 / 了解）与具体型号（MT6701 / MPU6050 / Saleae / tmux 等）。

> 顶部索引与末尾详表存在**有意重复**：顶部管"扫得到"，末尾管"说得清"。ATS 关键词两种写法都覆盖，不会漏。
